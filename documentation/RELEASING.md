# 公开源码和发布流程

## 精简的公开副本

在仓库根目录执行：

```sh
python scripts/prepare_publication.py
```

脚本按白名单保留源码、测试、模型、Gradle 构建文件、许可证和说明；排除构建产物、缓存、日志、IDE 配置、本机 SDK、私钥、上游商店素材与 `.git`。输出到 `.local-tools/publication/` 下新建的目录和 ZIP，不覆盖已有副本。扫描发现疑似秘密或本机用户路径时停止，不生成可发布 ZIP。

该副本不包含原仓库历史。上传前核对其文件清单；不要在未经检查的工作目录执行 `git add .`，也不要直接推送本机历史到上游仓库。导出副本保留上游声明与来源，但不是 GitHub 原生 fork 历史。

## GitHub 上传

1. 确定自己拥有写权限的目标仓库和公开范围。
2. 从经过检查的副本初始化 Git，检查 `git diff --cached`，设置自己的提交身份。
3. 将 remote 指向自己的仓库；Klick’r 的上游 URL 仅作来源参考。
4. 推送后核对公开文件、许可证及 README 链接。首次运行手动构建工作流验证 CI。

## APK 发布

- 为发行源码创建标签，从该标签构建，使用自己保管的签名。
- 校验包信息、arm64 架构、签名和 `zipalign`；记录 SHA-256。
- Release 同时提供 APK、对应源码下载入口、构建说明和许可证 / 第三方声明。
- GPL 对应源码包含生成和安装程序所需的修改及脚本。不能只发布 APK，也不能用隐藏的本机文件替代必要源码。
- 保留原版权、免责声明和修改日期；原始 LICENSE 不改写。依据 [GPLv3 第 4–6 节](https://www.gnu.org/licenses/gpl-3.0.html) 检查分发材料。
- 不上传任何私钥、令牌、账号配置或未经脱敏的用户数据。

本项目目前验证的是开发构建和针对性测试，尚未完成所有设备兼容性或全部第三方依赖的法律审计。发布前需审阅实际包含的依赖许可及 NOTICE。
